# MVP internal contract

The renderer calls one allowlisted IPC command with a plain JSON payload; secrets never enter saved workspace state or renderer responses. Modules own async state and emit `{type, data}` through the injected `onEvent`. Reject invalid IDs and stale account generations. Tests use injected transports; never mutate a real Steam account.

## SteamService (`desktop/services/steam.mjs`)

Named export `SteamService`, constructor `{ onEvent, fetchImpl?, SteamUserClass? }`.
Methods: `status()`, `login({accountName,password})`, `submitGuard(code)`, `logout()`, `ownedGames()`, `searchStore(query)`, `appDetails(appId)`, `startRun({appId,totalTargetMinutes?,stopAfterMinutes?})`, `stopRun(appId)`, `runs()`, `close()`.
Owned game `{appId,name,steamMinutes}`; app details `{appId,name,description,headerImage,developers,releaseDate,platforms,storeUrl}`. Status `{state,generation,steamId?,displayName?,guardPrompt?,error?}`; every start attempt has a new run UUID. Runs contain `{id,steamId,appId,generation,name,state,startedAt,stoppedAt,localElapsedSeconds,localElapsedMinutes,baselineSteamMinutes,steamMinutes,lastReadbackAt,readbackStatus,totalTargetMinutes,stopAfterMinutes,deadline,reason,requestStatus,stopStatus}`. Target/deadline and Steam readback are separate from monotonic local elapsed; local elapsed never becomes a Steam increment. Running/stopped request states are not server persistence acknowledgements.

Events `steam.status`, `steam.guard`, `steam.runs`. Credentials stay in memory; no stored refresh token. Login can remain pending during Guard, which arrives as an event. Disconnect/conflict/suspend invalidates owned async work, freezes sessions and never automatically resumes. Single stop sends the complete remaining active AppID set. `suspend()` and `close()` clean up owned sessions; cleanup without acknowledgement remains explicit unknown. Demo runs always retain fixture provenance and use a separate workspace.

## NativeStatsService (`desktop/services/native-stats.mjs`)

Named export `NativeStatsService`, constructor `{binaryPath?, steamLibraryPath?, fixture?, onEvent?}`.
`read({appId})` returns `{appId,accountId,achievements,stats,source,capabilities}`; achievements `{id,name,description,hidden,unlocked,unlockedAt?,globalPercent?}`; stats `{id,type,value,writable,reason?}` with `type=int|float|average`. Missing global percentage stays unknown. `apply({appId,expectedAccountId,changes:{achievements:[{id,unlocked,before?}],stats:[{id,type,value,before?}]}})` consumes one matching preview, enforces its client-library SHA-256 and old values, then returns per-item staging, store callback result and a fresh helper readback. Average stats cannot be directly assigned; malformed/protected schema fields cannot become writable defaults.

Each helper is standalone per AppID/command. Refresh callback/call-result identity and Store callback must match the expected context. API bool or matching local values alone never verifies storage. `verified` means matched successful Store callback plus a separate-process client refresh; `verification.independentServerRead:false` remains explicit. Missing refresh, wrong account, timeout and uncertain mutation remain unknown. A rejected batch keeps the batch failure while matching/unavailable individual readbacks remain unknown; a refreshed differing value can mark that item failed. Fixture verification is always `scope:fixture, steamVerified:false`. No real writes during development or CI. `close()` ends owned children and prevents late success. No Steam SDK/client libraries or built helper binaries in Git. Current native capability is guarded macOS arm64; Windows native support remains unimplemented.

## ResearchService (`desktop/services/research.mjs`)

Named export `ResearchService`, constructor `{fetchImpl?}`.
`research({appId,name,language?,requestId}, settings, signal)` returns `{appId,requestId,sources,reviews,summary,draft,citations,warnings,usage}`. Each source has URL/title/date/kind/acquisition status and actual obtained excerpt or explicit read-failed status, plus identity/coverage. Steam uses current `IUserReviewsService/GetAppReviews`; review paging/count/text and generation context are bounded. Search-only references, excluded game editions and failed reads cannot become article evidence. Draft and summary cite supplied source IDs, and generated first-person playing/testing experience is rejected.

Settings `{apiKey,searchApiKey?,baseUrl?,model,maxSources?,maxOutputTokens?}`. User selected Gemini as the only AI provider. Default base URL is `https://generativelanguage.googleapis.com/v1beta`; `generateContent` uses `x-goog-api-key`, JSON schema and no tools. Missing model/key cannot invoke AI. Independent Brave Web Search uses `searchApiKey` against the fixed official endpoint by game name; search title/snippet/raw response is transient. Only independently HTTP-obtained media text enters generation. Missing search credentials yields `missing_search_configuration` plus Steam-only coverage; it must not pretend external research occurred. No Google Search grounding/URL Context or OpenAI branch, no generic provider framework.

`translate({text,language},settings,signal)`, `shorten(...)`, `format(...)` return `{text,usage}` suggestions without mutating caller drafts. Shorten requires fewer than 200 Unicode code points and no links/tails/format tags; format rejects unsafe HTML/images/URLs. Whole-operation, request, redirect, response and context bounds apply; media DNS results are checked and pinned, private addresses rejected, redirects revalidated. Abort/timeout prevents late delivery. Errors are sanitized and failed paid requests are not automatically retried. `usage.calls` records provider, operation, requests/status and known usage; Gemini tokens remain null if not returned.

Before starting research, controller freezes `{taskId,ownerSteamId,language,baseRevision}` as trusted `result.origin`; the same origin is saved and returned. Renderer application checks the original account/task/language/revision. Acquired sources, summaries, suggestions and saved author drafts stay separate; controller version guards own any draft commit. Tests inject network fixtures and never supply credentials or invoke paid APIs.

## Workspace and local data

`Workspace` snapshots filter tasks and `runHistory` by `activeSteamId`; `exportBackup()` contains all owners without credentials. `recordRuns(runs)` commits a complete checkpoint batch once, and `recordRun(run)` is its single-item wrapper. Runs update by UUID; owner/AppID/generation are immutable, and a terminal record cannot resume using the same ID. Historical values are an explicit whitelist: elapsed, last Steam readback, conditions, times/reason/status and provenance. Fixture/imported history stays labelled. Load/import converts running records to `outcome_unknown` without generating elapsed, stopping timestamps or resumed sessions.

Repository updates are atomic and memory advances only after save succeeds. Workspace JSON is limited to 20,000,000 serialized UTF-8 bytes, with bounded record arrays. Backups strip secret/header/session slots, downgrade imported publication success and preserve drafts. Recovery validates the selected/previous backup before replacement and archives a corrupt original; it never silently resets a workspace. `SecretStore` stores keys separately with OS encryption or explicit session-only memory; AI credentials bind their destination origin. Credentials and browser/session files never enter IPC snapshots or backups.

Manual draft buffers retain their original owner/task/language/revision. A late autosave may explicitly name that original owner after the active account switches; the saved task must match that owner and CAS revision. It never changes the active account or authorizes Steam/AI/publication operations for another account. Calls without an explicit owner still use the active workspace account. Account changes replace the task view while retaining unsaved buffers until their original save succeeds.

## Publishing and desktop boundary

Renderer receives one allowlisted IPC bridge in a sandboxed, context-isolated page with Node integration disabled. Publishing uses an independent Steam-only account partition without the app preload; the operator logs in there. Frozen attempts bind owner/AppID/group/language/content/revision. Inspect/fill validates identity and destination, and never submits. The operator submits and records URL/provenance. Long-review automatic verification reads Steam and compares frozen content; short-review manual confirmation remains user-confirmed, and cannot be promoted by renderer input to automatically verified. Unknown submissions block blind retries; account changes/close cancel stale work and clear session ownership.

`--fixture` selects synthetic services and a separate workspace. `--smoke` requires fixture mode and a temporary data directory; it proves Electron/IPC/DOM fixture wiring only. First package is macOS arm64, ad-hoc signed and not notarized. CI has no account credentials, live Steam access, paid APIs or uploaded user/build artifacts.
