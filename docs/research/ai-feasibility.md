# 按游戏名调研并生成有来源初稿：API 可行性

调研日期：2026-10-17。关联 [Issue #4](https://github.com/TeaganRicardo/SteamCuratorHub/issues/4)，需求依据为 [REQUIREMENTS 第 5、9 节](../REQUIREMENTS.md)。调研起点的 `origin/main` 为 `de0adcbbb9df995e3663a45db10f834eaeecda88`，工作分支为 `docs/global-project-plan`；读取时分支 HEAD 为 `272498910bb8445c39936b2ca2954a10aa0c9822`。本文件所在最终提交以关联 PR 为准。

## 结论与证据边界

官方文档支持组成“确定游戏 → 读取 Steam 评论 → 按游戏名搜索媒体 → 读取实际可获取内容 → 保存来源关系 → 生成可编辑初稿”的链路。应用内 API 可以完成这些步骤，不要求用户先提供链接或游玩笔记。以下方案仍是工程建议，未替用户确定 AI 供应商、付费账户、预算或双语策略，也没有更改已确认需求。

本轮实际执行：读取仓库需求、Issue #4 与一手官方文档，逐页核实接口和限制。没有调用付费搜索/生成 API，没有使用密钥或 Steam 登录态，没有生成真实游戏的产品初稿，没有执行 Steam 账号写入。文档支持只证明候选接口存在，尚未证明目标游戏的资料覆盖、网页提取质量、中文成稿质量、调用成本和可持续使用条件。

## 最小数据流程

1. **绑定游戏身份。** 从用户已选定的 Steam AppID 建立一次研究任务，保存官方名称、已取得的本地化名称、作品类型及可核实的开发商/发行信息。缺失字段保持缺失。搜索关键词来自游戏名，AppID 是内部归属依据；不要求用户手填站外链接。
2. **独立读取 Steam 评论。** 用 AppID 调用评论接口，明确记录语言、排序、正负评价、购买类型、时间范围、页数和去重结果。评论获取失败不阻止站外搜索；“没有结果”“限流”“读取失败”分别显示。
3. **按名称发现媒体。** 首轮查询采用 `官方名称 + review/评测`；有歧义才补开发商、年份、完整副标题或官方别名。保存实际查询和搜索时间。搜索标题/摘要只用于候选筛选，不标记为已读取文章。
4. **核对作品并读取内容。** 匹配目标作品后取回正文或相关片段，记录读取成功、部分内容、登录/付费墙、无正文、拒绝访问等结果。读取失败的候选保留失败原因，不将搜索摘要伪装成正文。
5. **形成研究资料。** 将实际取得的评论和媒体片段整理为来源事实、来源观点及相互冲突的表述。每条摘要指向具体来源及已取得的范围。模型补充推断单独标记，不能回写成来源原文。
6. **生成新草稿版本。** 使用这次冻结的资料集合生成长评建议，保留引用关系、资料缺口与生成记录。展示后由用户编辑；生成结果不覆盖已经编辑的正文。研究和草稿分别保存，不因切换游戏、语言或刷新研究而改变其他任务。

以上步骤先实现为一个研究任务流程和少量明确的数据记录即可；当前没有必要建设可动态装载的供应商插件平台。

### Steam 评论接口须按当前文档迁移

直接打开 [旧 Get List 文档](https://partner.steamgames.com/doc/store/getreviews?l=english)时，页面已将 `/appreviews/<appid>?json=1` 标记为废弃，并指向 [IUserReviewsService.GetAppReviews](https://partner.steamgames.com/doc/webapi/IUserReviewsService#GetAppReviews)。新接口为 `GET https://api.steampowered.com/IUserReviewsService/GetAppReviews/v1/`，使用 `input_json`，公开评论可匿名读取；匿名请求有较低共享限流，可能缓存最多 10 分钟。

下面是**未执行的请求形状示例**；`TARGET_APPID` 在实际调用前替换为已选定的数字：

```text
GET /IUserReviewsService/GetAppReviews/v1/?input_json=<URL 编码后的 JSON>
{
  "appid": TARGET_APPID,
  "filter": 1,
  "languages": ["schinese", "english"],
  "review_type": 0,
  "purchase_type": 1,
  "num_per_page": 20,
  "cursor": "*"
}
```

该例为近期、全部评价、全部购买类型，语言和数量仅为验证样例，不是产品默认。迁移时不能继续使用旧字符串枚举、单数 `language` 或 `success` 字段判断；应校验 HTTP 状态和结构。分页保存游标并去重，空页才结束相应分页；有用评价排序不适合不设上限地遍历。来源记录保留 `recommendationid`、原文、语言和创建/更新时间；翻译另存。[迁移说明与枚举](https://partner.steamgames.com/doc/webapi/IUserReviewsService#migrating)

游戏名取得也需单独验证，不能假设所有商店数据接口匿名可用。官方 [IStoreService.GetAppList](https://partner.steamgames.com/doc/webapi/IStoreService#GetAppList)要求 Web API key，支持游戏/DLC 等筛选；它提供目录信息，不能独自解决媒体文章与具体版本的对应关系。本研究不把未取得凭据的目录接口视为已打通。

## 小规模候选组合

各候选都独立使用 Steam 评论读取；下表比较站外研究与生成。没有选择具体模型字符串，接入时需冻结已确认可用的模型、API 版本与调用参数。

| 候选 | 官方能力与最小组成 | 对本项目的判断和仍需验证项 |
| --- | --- | --- |
| OpenAI Responses + `web_search` + 必要的应用内网页读取 | 官方工具暴露 `search`、部分模型支持的 `open_page`/`find_in_page`，以及 URL 引用；可请求完整来源列表。见 [Web search](https://developers.openai.com/api/docs/guides/tools-web-search)。 | 可作为单一 AI 服务候选。需要解析工具结果和可见引用，验证媒体内容实际取得范围；只有引用链接时仍不能声称应用保存了原文。对不能取得可回溯片段的文章，补独立读取或标记证据不足。 |
| Gemini API + Google Search grounding + URL context | 搜索 grounding 返回查询、引用和 Search Suggestions；URL context 支持提供具体 URL 并返回读取尝试结果。见 [Search grounding](https://ai.google.dev/gemini-api/docs/google-search)、[URL context](https://ai.google.dev/gemini-api/docs/url-context)。 | 工具组合在文档上成立。现行 grounding 条款对结果保存、修改和自动收集链接另有约束，不能默认接入本项目的持久资料库与可编辑草稿。应先核实产品用法是否符合条款，再考虑此路线。 |
| Brave LLM Context + 一个生成 API，必要时补应用内网页读取 | [LLM Context](https://api-dashboard.search.brave.com/documentation/services/llm-context)返回按 URL 组织的实际提取片段及来源元数据，可约束返回 URL/上下文量。生成服务只接收选定片段。 | 将发现/内容与生成分开，有利于检验引用与任务归属，但增加一个服务及其费用、条款和故障面。返回的是相关片段，不能宣称读取整篇；索引时间与本次请求时间分开保存。 |

OpenAI 文档要求将网页结果的引用明确、可点击地展示；`sources` 列表与成文中的引文范围不同。默认允许实时访问也不代表每条来源均已重新抓取。接入时保留实际工具结果，不能仅保存最终一段生成文字。[OpenAI Web search：引用、来源、实时访问](https://developers.openai.com/api/docs/guides/tools-web-search)

Gemini URL context 的内容可能来自内部索引缓存或实时读取，且只处理给定 URL，不自动读取其嵌套链接；付费墙与需要登录的内容不应算作读取成功。其读取状态和引用是核对线索，不能代替逐条验证文章身份。[Google URL context](https://ai.google.dev/gemini-api/docs/url-context)

Gemini grounding 当前条款限制将返回链接自动收集后用于抓取/建索引，并对 Grounded Results 的存储和修改规定了具体限制与例外。因此，“抽取 Google grounding 的链接 → 自行抓取 → 建立长期研究数据库 → 任意改写发布”不能直接认定为适配的默认实现。这里记录的是供应商明确约束与产品适配待核项，不将本次调研写成法律结论。[Gemini API Additional Terms：Grounding with Google Search](https://ai.google.dev/gemini-api/terms#grounding-with-google-search)

Brave 的普通 [Web Search](https://api-dashboard.search.brave.com/app/documentation/web-search)返回标题、链接和摘要，不能等同正文；其 LLM Context 则返回提取内容。选择时须同时核实所选计划允许的保存/使用方式及媒体内容的处理范围，不能从“API 返回了文本”推断有整篇转载权。[Brave LLM Context](https://api-dashboard.search.brave.com/documentation/services/llm-context)

**建议的接入顺序：** 先做供应商无关的本地数据校验，再在一个服务组合中完成小样本端到端验证。最终接入前只确认当时必要的供应商/账户、费用上限与凭据保存方式；无须现在让用户一次选择所有模型或筛选策略。AI 订阅、旧原型的 Gemini 实现和服务名中的 `Free` 均不作为新 API 可用性或费用依据。

## 来源记录与作品匹配

下面是候选领域记录，属于实现建议，并非已确定的数据库结构：

| 记录 | 最少保留的信息 | 验证规则 |
| --- | --- | --- |
| 研究任务 | task ID、AppID、游戏身份版本、研究 revision、请求 ID、状态、开始/结束时间 | 一次结果只能提交到创建请求时的任务与版本 |
| 来源 | source ID、种类、请求 URL/实际 URL、标题、作者及日期（可缺失）、取得时间、取得方式、读取状态、已取得片段及其摘要/哈希 | URL 引用不自动升级为已取得正文；没有获得原文时不编造哈希 |
| 身份匹配 | 目标 AppID、正文里的作品名、开发商/年份/版本线索、匹配理由、匹配/不符/待核 | 同名、续作、原作/重制、DLC/本体、不同平台版本分别判断 |
| 摘要/断言 | 表述、事实/来源观点/模型推断、来源 ID 与片段位置、相互冲突的来源 | 生成推断不能当作来源事实；来源缺失时保留资料不足状态 |
| 草稿版本 | 正文、资料集合版本、引用映射、供应商/模型、生成参数版本、生成时间、用户修改版本 | 用户正文与研究摘要独立保存；应用新稿前检查原稿版本 |

判断同名游戏不能只用标题相似度或模型置信分数。优先使用正文中的完整名称与官方产品链接，再结合开发商、年份和版本线索；对重制版与原版明确单独匹配。DLC 文章只有确实讨论目标内容的部分才可引用，本体评论不冒充 DLC 评价。多平台文章保留平台背景，不能把主机性能评价转成 PC/Mac 性能事实。无法判定时将该来源留在“待核”，继续处理其他来源；只有所有关键资料都歧义时才需要用户辨认目标。

媒体发布时间、更新日期、本次取得时间和供应商索引时间不是同一字段。没有文章日期就显示未知，搜索结果显示的相对时间不擅自补成精确发布日期。短摘录、翻译和摘要与原文分开；本地研究保存不代表可以把媒体全文提交公开仓库或发布到 Steam。

## 生成约束与失败处理

生成输入应列出本次选定来源、可用内容和缺口；来源文本按资料处理，其中要求改写系统指令、导出凭据或执行操作的文字不获得工具权限。输出是可编辑研究初稿，不能自动当作作者亲历或自动进入发布操作。

没有用户游玩笔记也可以写资料驱动的分析，但不得新增“我游玩了 20 小时”“实测没有掉帧”“我解锁了全部成就”等个人经历。可采用“该媒体认为……”“本次选取的评论提到……”并保留来源关系。对玩家评论样本只能报告本样本观察，不能推导为全体玩家比例。语言流畅或模型生成成功均不能证明事实正确。

| 情形 | 候选处理 |
| --- | --- |
| 一方资料失败、另一方成功 | 保留成功资料和失败原因；标记覆盖不完整，生成时披露缺口，不补造站外媒体或 Steam 评论 |
| HTTP 429、暂时网络失败 | 有界重试并尊重可用的退避信息；重试使用同一任务标识并去重。鉴权、付费墙、身份不符不进入无限重试 |
| 内容不可取得或只返回搜索摘要 | 仍可显示候选链接；不给其添加正文摘要或当作已读媒体证据 |
| 来源互相冲突或时间跨度大 | 并列来源与日期，说明不能确定；不让模型静默择一变成事实 |
| 上下文超限 | 去重并按来源分块提炼，保留每块的来源关系与截断范围；为最终生成保留输出空间。不静默丢弃来源或将摘要冒充原文 |
| 用户取消、切换任务、刷新研究 | 尽力取消网络请求，并在写入前校验 task/AppID/revision/request ID；迟到结果不能覆盖当前任务。取消不承诺供应商已撤销计费 |
| 用户生成期间修改正文 | 返回的新稿保存成建议版本，比较原稿版本后再由用户应用；失败、超时、取消都保留现有正文 |
| 所有证据为空、均不符或无法读取 | 返回明确的资料不足结果及可重试项，不生成貌似完成调研的评测 |

成本按搜索/读取工具、模型输入（含取得内容）、输出及供应商另行计量的部分记录。一次用户操作可能触发多次搜索，不能拿“一个 API 请求”当一个搜索的费用。Google 官方说明搜索计量受模型版本影响，URL 读取内容计入输入；OpenAI 官方区分搜索工具成本。这里不固定价格或承诺免费额度。[Google Search 计量](https://ai.google.dev/gemini-api/docs/google-search#pricing)、[URL context token 计数](https://ai.google.dev/gemini-api/docs/url-context#token-count)、[OpenAI Web search](https://developers.openai.com/api/docs/guides/tools-web-search)

建议在开始前给出可控的查询、来源数、Steam 页数、上下文和输出上限，记录预估值与实际 usage，预算耗尽则返回部分结果。具体数值在小样本验证中确定，不作为已确认需求。密钥存放于本机凭据设施或明确的本机配置，日志和请求错误须脱敏；研究调用不发送 Steam 会话、真实用户数据库或无关账户信息。

## 可先实现的验证边界与下一步

这些校验不需要先选择付费供应商，也不需要正式 UI 或真实账号写入。首个实现只需固定 JSON 样本、研究结果校验和草稿版本提交边界：

- **来源导入与读取分级：** 将搜索摘要、已取得片段、读取失败分别处理；拒绝把无来源 ID 的断言写成有证据事实；支持缺失日期和部分读取。
- **身份匹配：** 样本覆盖同名、续作、原版/重制版、DLC/本体、平台差异、重定向和待核结果。被拒绝的来源不能参与该目标的草稿。
- **任务与草稿归属：** 模拟切换任务、并发刷新、取消和迟到响应；同时模拟用户修改正文，验证原稿不被自动覆盖。
- **有界资源与降级：** 模拟空结果、429、解析失败、上下文截断和预算耗尽，验证资料与原稿保留且不会无限循环。
- **生成验收：** 用固定资料集合检查引用存在、引用确实来自输入、缺口明确、没有新增个人经历。词语规则只能发现明显问题，仍需内容审阅，不能将自动检查通过称为事实完全可靠。

随后在选择服务和预算后，对公开游戏资料做小样本 API 验证：从游戏名开始，实际取得 Steam 评论及至少一篇身份匹配的媒体内容，核对提取范围、引用、中文初稿、取消/失败结果和实际 usage。测试集合应包含一个同名/版本歧义和一个不可读取页面；来源数量为该验证的门槛，不是永久产品最低要求。

Issue #4 的文档调研可据本报告交接；真实 API、内容质量和保存/发布用法的验证仍待进行。后续产品验收和 Steam 发布分别保留各自结果，本报告不宣称它们已经通过。
