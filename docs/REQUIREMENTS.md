# 产品需求草案

更新：2026-10-17。状态：已确认需求可按用户的自律开发授权逐项推进；技术可行性与未决产品选项继续分别验证和确认。

2026-10-17 用户授权全权自律开发，仅在必要时确认需求和实现细节。该授权允许推进已确认范围，不把原型行为或建议自动升级为产品决定；游戏实机、视觉与真实 Steam 验收仍由用户执行。

同日用户进一步要求自律推进到首版完整功能 MVP，并明确选择 **Gemini API**。本轮实现归属 [MVP #10](https://github.com/TeaganRicardo/SteamCuratorHub/issues/10)，使用说明与实际验收边界见 [MVP.md](MVP.md)。以下“工程默认”是为交付首版采用的可调整实现选择，不表示用户另行确认了对应产品偏好。

本文将用户明确要求标为“已确认”，从 Windows 原型提取的行为标为“原型行为”，流程改进标为“建议”。原型中的注释、测试和交接计划不是新增需求的确认依据。

## 1. 产品目标与范围

已确认：为一个 Steam 账号管理多个鉴赏组相关工作，覆盖查询游戏、模拟运行累计 Steam 时长、成就管理、评论研究、撰写个人长评、生成鉴赏家短评及发布准备。最终支持 Windows/macOS，首版可优先 Mac。

已确认：类 SAM 成就管理是必要能力；鉴赏家直接发布以技术可行为前提。项目使用公开 GitHub 仓库，跨 ChatGPT Chat Mode 与 Project 协作，仓库作为唯一状态基线。

建议：以游戏评测任务组织资料，但允许独立使用库查询、挂时长、成就、研究和编辑功能。完成时长或成就操作不应强制成为写作、发布的前置条件。

## 2. 游戏与评测任务

已确认：绑定 Steam 库、搜索游戏、查看商店及个人评论。每款游戏只向一个鉴赏组投稿，不支持同一游戏向多个鉴赏组分别发布短评。

原型行为：区分库内搜索与全商店搜索；近期游戏快速选取；按名称/时长等排序与分页；任务包含游戏、目标时长、截止日期、群组和草稿。创建默认 4 小时、7 天期限。

建议：来源记录与发布目标分别保存。来源可以先由用户手动指定；Curator Connect 自动发现作为独立能力验证。时长目标、截止日期均可不设置，不让一个普通写评任务必须填写计划。

待确认：领取来源是否始终为 Curator Connect，还是还包括群内分发 Key 等方式；领取来源与唯一投稿群组是否始终一致。不同游戏可以分别归属不同群组。

候选验收：切换游戏浏览不会改变当前评测草稿归属；创建/恢复任务后，编辑器、运行页和成就页都明确对应同一 AppID；重复任务有明确处理方式。

## 3. Steam 运行与时长

已确认：支持多款游戏同时模拟运行，以累计各自的 Steam 游戏时间。逐款队列不能替代并行挂时长需求。Mac 首版必须支持管理未安装、没有 Mac 版本的游戏，包括目标运行与成就能力；这是验收范围，不代表技术可行性已经验证。

原型行为：旧 UI 按定时器每秒增加本地 `PlayedHours`；新运行服务使用单调时钟、checkpoint 和可选 Steam URI 启动器。两者都不能作为已实现 Steam 挂时长的证据。

建议：分别展示 Steam 已记录总时长、当前会话本地计时和用户目标。以 Steam 回读结果确认累计效果；断线、暂停、退出和恢复分别有状态。手动“完成评测”只更新工作进度，不修改时长事实。

已确认：设定挂时长任务时可以选择 Steam 累计总时长目标；每次开启时也可快速选择本次自动结束时间。累计目标属于任务设置，本次自动结束时间属于当次运行设置，两者分开保存。

建议默认：两种停止条件同时存在时，以先达到的条件结束该游戏的本次运行；结束一款不影响其他并行游戏。本次定时结束不自动标记评测完成，也不改写任务的累计时长目标。启动前显示本次实际生效的停止条件；累计目标已达到时不再为追赶该目标启动运行。

工程默认：关窗或退出停止本应用的运行请求并清理；不在后台继续。累计目标与本次期限先到先停；单停不影响其他游戏。遇到协议冲突、掉线、睡眠或时钟异常时中断并保留未知/暂停状态，不自动续跑。运行历史单独持久保存本机 elapsed、最后 Steam 回读和停止原因，重启/导入时未结束记录转为结果未知，不自动恢复。真实游戏冲突行为仍需本机验收，相对时长快捷项和自定义结束时刻可在后续交互中调整。

建议：每款游戏独立展示运行状态与时长，支持分别启停；批量操作保留逐项结果。技术验证须确认多个 AppID 并行期间各自的 Steam 时长确实增长，不能仅验证本地多计时器。

候选验收：目标 AppID 被正确识别；启停可控；服务退出后不会遗留未知运行会话；Steam 端时长确实变化。Mac 验证必须覆盖用户指定的 Windows-only 且未安装的游戏；不能只用已安装的 Mac 游戏通过验收。

## 4. 成就管理

已确认：实际交付版本必须可修改成就，包括单项/批量解锁、重新锁定，以及统计值修改；同时提供成就搜索、全球解锁百分比、包括百分比的多种排序。Windows 旧版本只是参考原型，其只读实现不能作为需求降级依据。Mac 游戏覆盖要求见第 3 节。

原型行为：读取玩家成就和游戏 schema，合并中英文名称/说明、解锁状态、解锁时间并缓存；没有找到成就写入实现或全球解锁率接口。成就页主要展示列表。

建议：支持名称/描述/内部 ID 搜索，已解锁/未解锁筛选，按名称、全球解锁率、解锁时间排序；对拟修改项先呈现改动，再提交和回读。批量提交时保留逐项结果；未知百分比显示缺失状态，不当作 0%。

工程默认：隐藏成就默认折叠，用户可在成就页主动显示；正式剧透偏好仍可调整。

建议：统计值按实际类型显示与编辑，保留修改前值、提交值和回读值；成就和统计值分别呈现提交结果。技术验证需覆盖成就写入与统计写入，记录实际可写范围和失败原因。

候选验收：界面勾选不是成功依据；重新读取 Steam 后确认变化。不可修改项给出实际结果；失败不会错误显示成功或丢失未完成选择。

## 5. 商店与评论研究

已确认：商店评论查看、翻译和 AI 格式处理；调研范围同时覆盖 Steam 他人评论与站外信息，包括媒体测评。

原型行为：商店详情、双语官方介绍、玩家评论、单条/批量翻译、评论摘要、详情与评论独立降级，以及 Library/Editor 共享研究面板。

建议：保留原文、译文和来源链接，明确 AI 摘要对应哪些评论；评论研究与用户自己的评测草稿分开。搜索/切换任务取消旧请求，避免迟到结果写入其他游戏。

已确认：AI 能基于调研资料生成长评初稿，不要求用户提供游玩笔记。

已确认：站外调研按游戏名搜索，不要求用户先提供资料链接。

建议：从选定 Steam AppID 取得游戏名，必要时结合官方中英文名、开发商、发行年份核对同名游戏、续作、重制版和 DLC，避免把其他作品的媒体测评混入。搜索后实际读取可获取的资料，再生成初稿。手动链接导入不是当前已确认的必需功能。

待确认：评论和站外资料筛选范围。

建议：资料保留来源 URL、标题、日期和与目标游戏的对应关系；区分资料事实、来源观点与生成推断。摘要和初稿使用实际取得的内容；检索失败或资料不足时明确显示，不把模型记忆当作已调研来源。媒体文章提供必要摘录和摘要，不整篇复制。初稿避免虚构用户未提供的第一人称游玩经历。

## 6. 个人长评与群组尾巴

已确认：个人长评撰写、格式处理、发布，并添加对应群组尾巴。

原型行为：Steam BBCode 工具栏覆盖标题、强调、列表、链接、引用、代码、剧透、表格等；草稿按类型和语言保存。群组设置服务和双语尾巴存在，但主 UI 仍使用三个示例群组。

建议：保存正文与尾巴模板，按选定群组组合预览；重复保存、预览、发布不会重复追加。更换群组时替换选用模板，避免旧尾巴残留。

候选验收：切换群组、任务和草稿语言都不覆盖其他草稿；BBCode 有明确原文/预览；已发布内容与后续修改的草稿分别保存。

用户给定群组：浮生评测（45134494）、桃你欢心（45525570）。原始消息中的尾巴存在 Markdown/BBCode 混合转义，正式模板仍待用户核对；首版仅提供可编辑的群组链接模板作为工程默认，不声称其为用户正式尾巴。

## 7. 鉴赏家短评与全文链接

已确认：短评正文仅包含文字概括，无群组尾巴，不拼接全文链接。正文由个人长评总结删减为 200 字以下，中文字符、英文字母、符号计 1 字。个人长评的全文链接从另一个独立文本框输入/导入，分别保存、校验和填写到发布表单对应字段，不占短评正文计数。

原型行为：短评草稿、摘要服务、Recommended/NotRecommended/Informational 三态核心模型；正文组合器使用 grapheme 计数和 200 上限，并在提供群组时也向短评追加尾巴。网页自动填充脚本尚无全文链接参数。

建议：摘要保留长评观点，生成后可编辑；程序校验正文字符数和当前群组，不依赖模型自行遵守。原型给短评追加尾巴的行为已明确不适用于新版本。

待确认：允许恰好 200 字还是严格小于 200；空格、换行和复合 emoji 的计数；三态推荐是否全部保留。每款游戏的短评仅对应其唯一投稿群组。原型中的平台长度常量只是实现事实，Steam 当前表单限制另行验证。

工程默认：首版保守采用严格小于 200 个 Unicode 码点（最多 199），空格、换行和标点参与计数，复合 emoji 按其实际码点数计算；保留推荐、不推荐、信息三态。此计数规则不是 Steam 平台实测结论。

候选验收：准确计数中英混排和符号；修改链接或长评尾巴不会改变短评正文和字数；长评修改不会静默覆盖已编辑短评；独立全文链接字段对应正确游戏和账号；短评失败可独立重试。

## 8. 发布与领取

已确认：个人长评发布；技术可行时加入鉴赏家发布接口。未确认首版必须自动领取 Curator Connect 游戏。

原型行为：WebView2 Steam 登录及身份检查、长评/短评 DOM 填充、offer 发现和定位。脚本不提交。新准备/确认服务存在，但旧 UI 仍调用直接本地记账命令。

建议：首先验证真实网页流程，优先完成可靠的辅助发布；再决定是否提供应用内最终提交。单独记录目标 AppID、账号、群组、内容版本与发布结果，区分待发布、待核实、已核实、失败。超时后先查询结果，再决定重试。

候选验收：打开页面、填入文本、按下按钮均不直接等同成功；能够获取发布链接并核对结果。若只能人工确认，应明确记录其来源，不能宣称已自动核实。长评成功、短评失败时保留各自状态。

领取管理若保留，需要区分发现 offer、定位、用户领取和已核实领取。加入群组、拥有鉴赏家管理权限和拥有某个游戏分别判断。

## 9. AI、语言与保存

已确认：AI 采用应用内 API 接入，不以外部 ChatGPT 手动导回作为主要流程。2026-10-17 用户选择 Gemini API；具体模型由本机设置提供，不承诺固定模型、免费额度或价格。

原型行为：简体中文/英文 UI，双语内容回退与独立草稿；Gemini 翻译及摘要客户端，配置从环境读取；SQLite 保存任务、草稿、历史与发布快照。

建议：界面语言与文章语言分开选择；查看他人评论、切换界面语言不会修改作者的草稿。先提供保存/恢复和备份导出，跨设备自动同步单独定范围。

工程默认：Gemini 是首版唯一 AI 供应商，负责研究稿、翻译、短评摘要与格式处理；按游戏名发现媒体使用独立 Brave Web Search，再由应用实际取文，搜索片段不视为已读正文。Brave 是检索工程选型，不是第二家 AI 供应商，也不是用户额外指定的产品要求。Gemini/Search 密钥本机填写，开发与 CI 不执行付费调用；缺搜索密钥时明确报告媒体覆盖不足并保留 Steam 样本。基于当前 Google Search grounding 的结果使用约束，首版不把 Grounded Results 或其链接自动改作可编辑资料库流程。

工程默认：首版简体中文界面，文章语言与双语草稿独立；草稿版本、AI 建议及资料来源分开保存，应用建议须匹配原任务、账号、语言与草稿版本。凭据使用本机系统加密保存，也可仅本次会话使用，不能随工作区备份导出。双语界面、后续其他模型服务和跨设备同步仍待单独定范围。原型服务名中的“Free”不构成当前免费额度承诺。

候选验收：AI 失败保留原文和已保存草稿；修改建议可预览；重启恢复数据；凭据与可公开项目内容分开保存。

## 10. 交付与技术决策

本轮范围：按用户的完整 MVP 指令完成生产模块、桌面工作流、保存恢复、离线验证、独立审查与本机构建；真实 Steam 时长/写入、真实发布、付费 API 和视觉验收各自保留结果门槛，不因开始产品开发而视为已通过。

已确认：跨平台版本重新寻找技术栈，不需要复用当前 Windows 原型代码。原型只提供功能与交互参考，不作为新项目的代码基础或技术约束。框架、Steam 本地接入和网页会话方案须根据 Mac/Windows 需求重新评估。

工程默认：首版采用 Electron + Node.js、独立 Objective-C++ 原生 helper 和独立 Steam 网页会话，优先提供 macOS arm64 包；本地存储采用有界 JSON 工作区与单独加密凭据。安装包为 ad-hoc 签名，未 Developer ID 签名/公证；最低系统版本与 Windows 原生写入/安装包尚未验收，不改变最终 Windows/macOS 目标。

首版验收应同时包含功能检查和用户本机操作结果。公开仓库中只维护开发基线；用户运行数据的备份/跨设备同步不是 GitHub 项目状态管理的同一件事。

已于 2026-09-22 确认：单游戏单投稿群组；Mac 首版覆盖未安装、无 Mac 版本的游戏；多游戏并行挂时长；成就单项/批量解锁、重新锁定和统计值修改；应用内 AI API 接入及无需游玩笔记的调研初稿生成；调研覆盖 Steam 评论和站外媒体；短评无尾巴且全文链接使用独立文本框；重新选择跨平台技术栈，无旧代码复用要求。

已补充确认：挂时长任务可设 Steam 累计总时长目标，每次启动可快速选择本次自动结束时间；站外调研按游戏名搜索；完整首版 MVP 自律开发至交付；AI 使用 Gemini API。

下一阶段按 [MVP #10](https://github.com/TeaganRicardo/SteamCuratorHub/issues/10) 收敛最终实现、审查与构建证据，并由用户按 [MVP.md](MVP.md) 执行真实验收；双语界面、领取自动化、后台持续运行和云同步等新增范围另行确认。

其他边界在对应开发任务开始前确认，不要求一次完成所有产品决策。
