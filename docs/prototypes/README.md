# 第一轮交互讨论稿

关联 [#13](https://github.com/TeaganRicardo/SteamCuratorHub/issues/13)。此目录只存在于 `codex/ux-discussion-20261021` 讨论分支，不合并到正式应用。当前 MVP 界面没有作为设计基线复用。

双击 `workflow-discussion.prototype.html` 即可打开；无需安装依赖。也可以在本目录运行 `python3 -m http.server 8765 --bind 127.0.0.1`，访问 `http://127.0.0.1:8765/workflow-discussion.prototype.html?variant=A`。方案参数支持 `A`、`B`、`C`；底部箭头与左右方向键可以切换，输入文字时不接管方向键。

全部游戏、账号、读数、来源、写入和发布结果均为合成演示。没有网络请求、真实凭据、真实操作或持久保存；所有状态只在页面内存中保留，刷新恢复初始值。

下面的操作数从游戏已选中且相关区域可见时起算，控件激活计一次；它们用于比较路径，未经用户实测或效率验收。

| 方案 | 主入口与信息层级 | 常用路径与操作次数 | 取舍 |
| --- | --- | --- | --- |
| A 以游戏为中心 | 先选游戏，任务与稿件围绕同一 AppID | 当前游戏单停或预览成就 1 次；换游戏后操作 2 次；从运行到稿件 1 次 | 一款游戏上下文清楚；并行总览需要更多注意力 |
| B 多游戏并行总览 | 多游戏运行表是首页，选中游戏在同一工作台处理 | 任意游戏单停 1 次；选中另一游戏并预览成就 2 次；选中游戏到稿件 1 次 | 并行控制直接；需要同时理解总览和选中项 |
| C 按评测进度组织 | 先按评测阶段找游戏，独立运行条常驻 | 运行条单停 1 次；选卡片再处理 2 次；更改阶段不退出当前游戏上下文 | 便于写作进度；不宜把阶段误当成 Steam 或发布事实 |

本轮只决定工作如何组织。图形、配色、字号、导航名称、正式群组尾巴和完整表单不是已确认设计。

## 可讨论的状态和路径

- 登录始终保留账号、阶段和验证上下文；切换情境可查看 Guard 与断线后的反馈。断线中断原运行，演示恢复认证不会自动续跑。
- 同一游戏或其他游戏运行时都可以读取、预览和演示修改成就。未知写入保留状态并阻止新写入，先独立回读核对；运行集合不因此被停止。
- 长评、短评、独立全文链接分别编辑。合成研究建议先保留为建议，主动应用才变为作者稿件；版本冲突保留本地文字。
- 发布先冻结内容和目标，再核对网页身份、辅助填表、本人提交和核实结果。长评与短评结果分别记账，本人确认不冒充应用回读核实；未知提交阻止再次准备。
- 工作区账号、网页发布账号和本机 Steam 客户端账号各自核对。演示状态可展开查看，所有观察都标明合成来源。

## 第一轮需要用户介入的决定

选择以 A、B 或 C 为继续讨论的基础，也可以指定组合；同时指出最常重复的两项操作。此后才进入第二轮：具体操作顺序、错误恢复、信息密度与点击成本，再由用户明确确认正式实现方向。
