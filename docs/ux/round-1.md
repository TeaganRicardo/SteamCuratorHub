# 正式界面：第一轮工作流方向

日期：2026-10-21。关联 [#13](https://github.com/TeaganRicardo/SteamCuratorHub/issues/13)、[#10](https://github.com/TeaganRicardo/SteamCuratorHub/issues/10)。

状态：**用户已于 2026-10-21 选择“游戏工作台”作为主结构。** 明确选择为“左侧选游戏，右侧完成运行、成就、研究与写作，底部常驻并行运行”。另外两种结构保留为本轮对照；下一轮见 [round-2.md](round-2.md)。当前分支 `prototype/ux-direction-20261021` 保存可抛弃的低保真草图；不要把此分支直接合入产品。生产入口、现有界面及后端保持原样。

## 这轮要解决的问题

打开应用时，用户主要是在管理一款游戏、推进若干评测，还是集中管理多款游戏的运行？三种答案需要不同的信息层级。先确定入口和工作上下文，再讨论视觉、密度、快捷操作和细节。

依据 [REQUIREMENTS.md](../REQUIREMENTS.md)：原 MVP 界面只作为功能验证壳，正式界面实现前须先经过多轮交互协商；多 AppID 必须并行运行，同一 AppID 的成就操作可同时进行；游戏、唯一投稿群组、研究、草稿和发布目标需要保持明确归属。时长或成就完成不能成为写作的前置条件。

## 三种结构

| 方案 | 首屏与主要操作路径 | 适用工作习惯 | 需要用户权衡 |
| --- | --- | --- | --- |
| 游戏工作台（已确认主结构） | 左侧选游戏；右侧在同一游戏下进入运行、成就、研究写作、发布准备；底部保留并行运行 | 通常围绕当前一款游戏连续处理多个环节，也会让其他游戏同时运行 | 单款上下文清楚；大量评测的全局进度需要另设总览 |
| 评测任务看板 | 先按待研究、撰写中、待发布找任务；选中后在下方展开完整工作区 | 大多数时间在管理多篇评测和投稿进度 | 评测进度突出；独立使用时长或成就工具时会多一层任务上下文 |
| 多游戏操作表 | 首屏集中显示多款游戏的运行、Steam 分钟和目标；选中一款后在表格下方操作 | 日常经常同时启停多款游戏，时长与成就管理比写作更常用 | 多游戏情况容易扫描；长文写作需要占用更多垂直空间 |

“游戏工作台”已经用户选择。其上下文围绕同一 AppID 共享任务、群组、草稿和发布目标，其他运行持续可见；本轮只确认这一结构，不代表接受全部草图细节或批准正式前端实现。

## 可操作草图

在此分支根目录运行：

```sh
npm run prototype:ux
```

打开 `http://127.0.0.1:4317/`，用底部切换器或左右方向键切换方案。输入框内的方向键保留给编辑。可直接使用：

- `/?variant=workspace`：游戏工作台。
- `/?variant=board`：评测任务看板。
- `/?variant=table`：多游戏操作表。

草图只提供内存示例，不读取真实账号、数据库、密钥或本地 Steam 客户端。预览服务仅监听本机回环地址，只提供这一页；页面的连接策略禁止对外请求。关闭服务并重新运行会重置全部示例修改。

可尝试的路径：

1. 两款游戏处于运行请求中；进入其中一款的成就页，预览和确认固定示例更改。另一款继续显示运行；单停一款后保留另一款。
2. 在研究与写作中手改草稿，切换另一款再切回来，检查各自的作者草稿保留。打开查找面板不会切换当前编辑任务；明确点击“进入”才切换。
3. 用预览底部的连接场景模拟 Guard、断线和会话失效；账号名与阶段保留在同一上下文，草稿仍可编辑。恢复连接后旧运行保持中断，必须手动启动。
4. 将写入结果切换为“结果未知”，再执行一次示例预览/写入；本游戏显示核对入口并阻止直接重试，切换游戏不会清除此记录。核对不自动重放写入。
5. 分别准备长评和短评，检查独立的全文链接、唯一投稿群组、冻结目标和本人提交的交接位置。草图不打开 Steam，也不提交评测。

嵌入聊天的版本由同一 `ux-prototype.fragment.html` 提供，宿主提供方案切换和场景控制；独立预览补上本地切换器。设置面板、搜索结果和状态值是示意，当前成就/统计预览采用固定选择，不代表全部正式编辑能力已经设计完成。

## 各方案共有的状态与恢复约束

- Steam 账号及认证阶段在应用顶部持续可见；Guard 和重试保留在同一上下文。
- 运行托盘独立于当前任务，逐款启停；Steam 上次读回分钟与本机计时分开显示。
- 成就写入前显示账号/游戏、旧值与新值；未知结果保留并要求先核对。原生操作本身串行，不能据此全局停跑。
- 研究材料、AI 建议和作者草稿分别展示；应用建议需要用户动作；查找游戏不暗中替换写作目标。
- 长评预览含群组尾巴；短评不加尾巴或正文链接，全文链接单独填写；长短评准备与结果各自独立。
- 设置、凭据和恢复采用统一入口；离线编辑可用。正式密钥、登录和操作证据仍由既有后端契约管理。
