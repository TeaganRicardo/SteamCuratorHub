# 工作台内的连接、任务与恢复流程草案

日期：2026-10-21。关联 [#13](https://github.com/TeaganRicardo/SteamCuratorHub/issues/13)、[草稿 PR #19](https://github.com/TeaganRicardo/SteamCuratorHub/pull/19)。

上一轮已确认的游戏工作台、正文优先、按需展开资料、可拖拽宽度、输入即排版和复制时输出 Steam 格式继续保留。本轮补齐剩余核心路径，以下为可讨论的交互建议，不能据此声称用户已确认最终前端方向。

## 本轮问题与方案

连接、查找游戏或恢复数据时，作者能否留在同一个工作台，清楚知道当前账号、游戏、草稿和运行的状态？本版建议把连接详情、查找和设置放在工作台主区域，左侧任务与底部运行信息继续可见；返回当前游戏即可继续编辑。

| 路径 | 操作与反馈 | 恢复与上下文 | 主要点击成本 |
| --- | --- | --- | --- |
| 首次连接 | 连接详情 → 示例账号连接 → 连续显示提交、Guard、验证、成功 | 始终显示同一示例账号；正文可继续编辑，密码不保存 | 打开连接详情 1 次；认证步骤取决于 Steam |
| 会话恢复 / 断线 | 状态条持续显示恢复或第 1–3 次重连；成功或失败后都有可操作结果 | 运行中断记录分别保留本机分钟和 Steam 上次读回；恢复连接不恢复运行 | 连接详情 1 次；读回后手动启动 |
| 查找与建任务 | 查找 → 库内 / 全商店搜索 → 结果详情 → 选择唯一投稿群组 → 建立任务并打开 | 浏览详情不切换正文；已有任务显示群组并直接打开，不能重复创建覆盖归属 | 查找 1 次，结果 1 次，选群组后创建 1 次 |
| 运行与成就 | 单款启停、独立累计目标和本次期限；同游戏运行中可预览和演示写入 | 未知结果只能先重新读取，再由本人核对；不重放写入、不改运行集合 | 预览与确认 2 次；未知结果核对 2 次 |
| 服务配置 | 设置 → Gemini / 媒体搜索状态与示例配置，区分系统加密和仅本次 | 缺媒体搜索明确显示覆盖只有 Steam 评论；生成失败保留正文和既有建议 | 设置 1 次；示例配置 1 次 |
| 备份恢复 | 设置 → 生成示例备份 → 检查恢复内容 → 对照当前与备份正文 → 明确恢复 | 有运行时先停止，再单独恢复；备份不含凭据或 Steam 会话，导入结果降为待核实 | 设置 1 次，检查与恢复各 1 次；有运行时增加停止 1 次 |
| 发布准备 | 长短评分别准备版本 → 演示目标检查与填表 → 本人提交记录 → 结果链接 → 核对 | 修改正文使旧准备不能再次填表；未知提交先核对；长评示例读回与短评人工确认分别记录，历史版本保留 | 每篇准备与目标检查各 1 次，实际提交和结果核对另计 |

## 运行与场景

```sh
npm run prototype:ux -- --round=4
```

打开 `http://127.0.0.1:4320/?variant=flows`。页面底部的演示场景可切换首次登录、会话恢复、断线重连、失效、仅本次保存，以及成就未知结果和生成失败。聊天预览提供相应的场景选项。场景按钮只推进合成状态，没有真实网络、定时重连、Steam 凭据、付费调用、文件读写或发布。

建议按以下顺序尝试：

1. 先在正文输入一句话，再查找“雾港”，浏览结果后返回；原游戏和正文应保持。选择群组并建立任务后，才进入新游戏工作台；已有任务直接打开。
2. 切到断线重连，依次演示三次失败，再使用保存的会话恢复。底部运行数应保持 0，原稿仍在；读回后手动启动一款。
3. 运行中切到成就，将演示结果设为未知，执行预览与确认。先重新读取，查看示例读回值，再确认已核对；另一款运行不受影响。
4. 准备一篇长评，返回正文修改，再回发布准备；原准备正文仍可检查，但旧版本不能再填表。重新准备、记录本人已提交后，需要结果链接并核对，才解除重复准备门禁；短评的人工确认与长评示例读回分别显示。
5. 生成备份示例，手改正文后检查恢复对照。有运行时先停止，再明确恢复；导入发布、成就和运行证据均需重新核实，连接与服务配置不随备份替换。

## 证据与实现边界

一次性 DOM 机械检查已覆盖任务与草稿归属、有界重连且不自动续跑、Guard 连续状态、同游戏未知写入核对、发布准备版本失效与长短评独立来源、备份导入来源降级与凭据隔离、生成失败保留正文。本机通过 35 个桌面模块语法检查、241/241 离线测试（0 skip）。

浏览器实际输入“保留本次修改”，查找“雾港”并选择桃你欢心建立任务；返回星海旅人后手改文字仍在，原两款运行仍保留。实际演示三次重连失败后，界面优先显示“再次尝试保存的会话”，账号密码表单只在主动选择重新认证后展开；恢复过程连续显示，成功后运行数保持 0，并逐款保留中断记录。该检查促成了重连失败时的主入口修正。其他恢复路径的本轮证据为合成 DOM 检查，不写成真实 Steam 或用户视觉验收。最终提交与对应 CI 记录在 PR #19。

本轮扩展仍是可抛弃草图；没有新增已确认产品偏好，也没有将原型状态逻辑作为正式服务实现。示例结果链接只用于检查界面门禁，不访问页面，不能证明 Steam 当前字段或发布成功。真实 Steam、付费 API、硬件/游戏与用户视觉验收继续各自保留门槛。正式前端进入实现仍需按 #13 获得用户对整套方向的明确确认。
