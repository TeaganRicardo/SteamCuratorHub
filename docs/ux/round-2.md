# 游戏工作台：第二轮研究与写作布局

日期：2026-10-21。关联 [PR #19](https://github.com/TeaganRicardo/SteamCuratorHub/pull/19)、[#13](https://github.com/TeaganRicardo/SteamCuratorHub/issues/13)。

## 已确认的决定

用户在第一轮明确选择“游戏工作台”：左侧选游戏，右侧围绕当前游戏完成运行、成就、研究与写作，底部常驻并行运行。此决定已写入本分支 [REQUIREMENTS.md](../REQUIREMENTS.md)；正式界面仍需后续交互收敛和最终方向确认。

用户已选择 **“正文优先，资料按需展开”**，并补充：“允许拖拽宽度。另外确保输入即预览，只在复制时带上格式，无需切换预览和编辑。” 当前收敛版本见 [round-3.md](round-3.md)；本文件及第二轮原型保留为比较快照，其中的编辑/预览切换已被新规则取代。

| 布局 | 主要路径 | 取舍 |
| --- | --- | --- |
| 资料与正文并排（对照） | 进入研究与写作后，直接选择来源、对照 AI 建议和编辑正文 | 查证与写作无需反复打开面板；正文宽度较小 |
| 正文优先，资料按需展开（已选定） | 进入后先看到正文；点“查看资料与建议”展开右侧面板，查完可收起 | 长文编辑更集中；查证时多一次展开/收起 |

后续只沿“正文优先”的方向细化，不再把并排显示作为待选主布局。资料仍可在需要时持续展开，并允许用户自行调宽。

## 共用的交互提案

这些是供本轮讨论的具体提案，不是新增确认需求：

- 当前游戏、AppID、唯一投稿群组固定在工作区上方；文章语言独立选择。
- 作者长评与鉴赏家短评在同一编辑区切换，各自保留中英文内容；全文链接仍为短评之外的独立字段。
- 来源原文、AI 建议与作者正文分别呈现；应用前先对照，应用后保留上一版作者正文。
- 生成建议后继续手改正文，会使旧建议无法直接覆盖新版本；可选用片段或重新生成。切换游戏或语言不会重新归属旧建议。
- 底部运行托盘默认显示每款名称、运行状态和单停；展开可查看 Steam 上次读回与本机本次时长。
- 点击“检查发布目标”只核对当前游戏、群组、语言与长短评，保留本人提交和分别核验的既有边界。发布流程细节留到后续轮次。

## 草图与尝试路径

第一轮原型仍保留；第二轮在相同的可抛弃分支内，使用另一端口以便两轮可同时查看：

```sh
npm run prototype:ux -- --round=2
```

- `http://127.0.0.1:4318/?variant=split`：资料与正文并排。
- `http://127.0.0.1:4318/?variant=focus`：正文优先，资料按需展开。

可比较这些路径：

1. 查看 Steam 评论和媒体示例摘录，边查边编辑正文；在正文优先方案中尝试展开和收起资料。
2. 对照一份 AI 建议，再修改作者正文，检查旧建议的应用入口被禁用；重新生成示例建议后才可应用。查看保留的上一版。
3. 分别修改两款游戏、两种语言、长评与短评；切换后检查各自内容与群组归属。全文链接按游戏与语言保留。
4. 保持两款并行运行，编辑或应用建议后单停一款，确认另一款保留；展开托盘检查两种时长区分。
5. 检查发布目标后返回编辑，确认草稿与上下文保留。

全部数据是内存中的合成示例。没有 Steam、AI、搜索、网页发布或真实文件保存；关闭草图会重置示例修改。“已保留”仅指当前草图内存，不代表生产持久化或真实平台结果。
